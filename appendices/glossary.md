# 附录：术语与实验记录

| 术语 | 在本书中的意思 | 易混边界 |
|---|---|---|
| SoC / MCU | 集成系统功能的芯片 / 微控制器 | 芯片不是完整开发板 |
| 模组 | 芯片及部分外围集成模块 | 天线、存储配置会影响实际使用 |
| GPIO | 可配置输入输出 | 编号不是排针序号 |
| ADC | 电压到数字编码 | 分辨率不是准确度 |
| PWM | 周期脉冲的占空比控制 | 并非直接输出平滑模拟电压 |
| I2C / SPI / UART | 三类不同的串行接口 | 同样四根线不代表兼容 |
| Flash / RAM / PSRAM | 非易失存储 / 工作内存 / 外部扩展工作内存 | 不同存储的寿命、速度与使用限制不同 |
| 固件 | 在设备中执行的软件集合 | 不只包含用户写的一个函数 |
| 状态机 | 状态、事件与转移规则 | 有限状态帮助说明例外与停止条件 |
| 任务 / 队列 | 调度单位 / 消息传递机制 | 更多任务不等于更多计算资源 |
| BLE | 蓝牙低功耗协议体系 | 不等于经典蓝牙 SPP |
| Thread | 基于 IPv6 的低功耗网状网络 | 不直接定义 Matter 全部应用能力 |
| Matter | 智能家居应用互操作标准 | 可通过不同 IP 网络承载 |
| MQTT Broker | 根据主题转发消息的服务 | 消息确认不自动等于业务持久化 |
| OTA | 通过网络等方式更新设备固件 | 下载成功之后还要验证、启动与恢复 |
| Secure Boot | 启动时验证受信任固件 | 与 Flash 加密职责不同 |
| 滞回 | 上下阈值之间保持状态 | 可以减少临界区反复切换 |
| 幂等 | 重复操作不产生额外业务效果 | 必须按具体业务定义 |

## 一页实验记录模板

每次实验保存下列信息，故障时先比对版本和连接，不凭记忆判断“与上次一样”。

| 项目 | 要记录什么 |
|---|---|
| 硬件 | 板卡修订、模组料号、外设型号、连接表 |
| 环境 | 系统、工具链、核心与库的完整版本 |
| 电源 | 来源、接入点、电压、负载与共地方式 |
| 软件 | Git 提交、配置参数、日志通路 |
| 预期 | 操作后什么时间内发生什么变化 |
| 证据 | 原始日志、CSV、测量值、实际现象 |
| 故障注入 | 断网、服务停止、无效数据或传感器离线 |
| 恢复 | 是否自动恢复、是否需要重启、旧状态如何处理 |
| 结论 | 已证实什么、尚未验证什么、下一步只改变什么 |

## 选看：还可以向哪里延伸

音频与语音可继续研究 I2S、采样率、DMA、声学结构和本地识别；摄像头与视觉需要同时考虑接口、帧缓存、PSRAM、镜头和照明；USB 项目应分清 Host、Device、USB-Serial-JTAG 和板卡供电角色。CAN/TWAI 还需相应外部收发器及物理层设计，不能直接把芯片逻辑引脚连到 CAN 总线。

这些方向各自能形成独立专题。本书不把它们压缩成“接模块就能完成”，先建立主线，再按真实需求扩展。对应目标芯片的外设目录，是继续学习比搜索任意“ESP32大全”更可靠的入口：[S3 外设 API 总目录](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/index.html)。
